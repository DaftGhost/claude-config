# DTO 与 Entity 字段类型规范

本规则只约束 `dto`、`entity` 目录下字段的类型选择、协议兼容性和数据库映射。DTO 与 Entity 可以使用不同类型，跨层转换必须通过明确的 Mapper 或转换逻辑完成。

## 枚举使用边界

### 使用枚举

同时满足以下条件时，使用枚举：

- 取值集合有限且稳定。
- 新增值需要修改代码并随服务发布。
- 字段表达本服务拥有的业务语义，而不是配置项或供应商维护的数据。
- 代码能够定义未知值、历史值和非法值的处理方式；无法定义处理方式时，不要让枚举转换静默变成 `null` 或任意默认值。

### 不使用枚举的场景

满足以下任一条件时，保留协议或数据库定义的原始字段类型，不使用枚举：

- 外部协议允许扩展，或数据中可能出现当前代码未定义的值。
- 字段包含未知历史值，系统需要读取、保存或原样返回这些值。
- 字段由配置中心、数据库运营数据或供应商动态维护。

字段类型按协议或数据库的实际定义选择，不要为了规避枚举而改变字段类型，也不要把未知值强制转换为 `null`、空字符串或某个枚举常量。

### DTO 与 Entity 的分层规则

- 外部协议 DTO 优先保留线上字段的原始值，以保证向前兼容和未知值透传。只有当协议取值由本服务控制且满足枚举条件时，才在 DTO 中使用枚举。
- Entity 只有在数据库 code 属于稳定业务字典、枚举常量与数据库 code 一一对应，并且已有数据不会出现未定义 code 时，才使用枚举。
- 数据库 code 可能由外部系统或运营配置扩展，或者历史数据可能包含未知 code 时，Entity 也保留原始字段类型，不要仅因为字段名称像状态或类型就定义枚举。
- DTO 使用原始值、Entity 使用枚举是允许的。转换逻辑应明确区分合法值、未知值和非法值，不要依赖字段类型相同来省略边界校验。

## 枚举序列化与数据库映射

- 枚举必须有明确、稳定且唯一的业务 code。数据库列和外部协议均不得隐式依赖枚举声明顺序或 `name()` 结果。
- 数据库存储值就是枚举内部的稳定 code，且读写不需要格式转换或组合拆分时，使用 `@EnumValue` 做直接 code 映射。
- 数据库存储值与枚举常量之间存在格式转换、组合拆分、兼容旧值或其他确定性的本地转换逻辑时，使用自定义 `TypeHandler`，并在 Entity 字段上显式声明。`TypeHandler` 必须同时说明读取和写入规则、空值处理以及未知或历史值处理方式。
- `TypeHandler` 只负责确定性的类型转换，不负责查表、业务判断、网络调用或默认值兜底。需要这些行为时，在持久化层之外完成映射；需要保留未知原始值时，保留字段的原始类型。
- `@EnumValue` 只表示直接 code 映射，不能替代 `TypeHandler`，也不能掩盖数据库值与业务值之间的转换。
- 禁止使用 `Enum.ordinal()` 或任何依赖枚举声明顺序的方式持久化或序列化。新增、删除或调整枚举常量不得改变已有数据的含义。

## 新增或修改字段时的检查项

1. 确认字段来源是内部业务、外部协议、配置数据还是供应商数据。
2. 确认取值集合是否允许新增，以及未知值和历史值是否需要保留或透传。
3. 分别确认 DTO 的协议类型、Entity 的数据库类型和两者之间的转换规则，不要让一层的类型选择约束另一层。
4. 若使用枚举，确认每个业务 code 的唯一映射、序列化形式和非法值处理方式。
5. 若使用 `@EnumValue` 或 `TypeHandler`，核对已存在数据的读取、写入、空值和异常路径，避免映射失败后静默丢失数据。
